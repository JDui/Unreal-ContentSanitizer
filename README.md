# Unreal 内容重复整理器

Unreal 内容重复整理器是一款 Unreal Engine 编辑器资产卫生工具，首要目标是提供**安全、可解释的重复资产检测、整理与引用重定向**。

当前重复检测实现只处理完全重复的 `Texture2D`，分别验证源数据和行为设置，提供只读审查、显式预检，并使用 Unreal 原生资产整理接口执行变更。

## 新阶段定义（2026-10-28 已确认）

当前阶段交付两条完整流程：**Texture2D 重复整理**与**单资产孤岛清理**，正式验收必须覆盖 **UE 5.5 和 UE 5.8**。权威约定见 [`AGENTS.md`](AGENTS.md)，实施顺序与现状缺口见 [`docs/IMPLEMENTATION_PLAN.md`](docs/IMPLEMENTATION_PLAN.md)。本节定义目标，不代表功能已全部实现或两版引擎已通过验证。

| 功能 | 已确认的阶段边界 |
|---|---|
| 重复整理 | 不扩展重复检测类型；默认全 `/Game` 比较，仅整理目标范围内的来源资产；优先保留范围外的等价资产，支持手动选择主资产 |
| 孤岛清理 | 检查贴图、材质/材质实例、静态网格和骨骼网格的单资产外部引用；不做孤岛簇或从地图入口推导不可达资产 |
| 材质关联 | 作为网格的展示与筛选信息，不决定网格是否被使用 |
| 修改流程 | 审查、加入队列、只读预检、明确确认、执行前复查、执行后验证；展示范围外引用包的修改影响 |
| 安全表述 | “未发现引用”是有覆盖边界的观察结果，不是绝对未使用证明；已知引用和失败的必要检查不能靠确认绕过 |

工作区已实现两条计划、预检、确认、执行与验证流程，手动主资产选择、独立重定向器清理及双引擎隔离测试入口也已补齐。完整自动化结果与剩余 GUI/发布验收限制见 [验证记录](docs/VALIDATION_2026-10-28.md)；已有按钮或自动化通过不代表正式阶段验收完成。

## 已有重复整理流程

- 明确区分**清理目标范围**与**重复比较范围**；
- 从窗口打开时默认清理目标为 `/Game`；从内容浏览器右键目录时，仅将所选目录设为清理目标，不会自动开始扫描；
- 开始扫描后默认以整个 `/Game` 作为重复比较范围，因此可以发现“所选目录中的资产”与“工程其他目录中的资产”之间的重复；
- 只有清理目标范围内的重复资产允许进入整理计划，比较范围内的其他资产只作为参照或主资产候选；
- 当重复组存在清理目标之外的等价资产时，优先将目标范围之外的资产作为主资产，避免把公共资产反向整理到待清理目录；
- 大工程扫描按帧推进，显示当前阶段、数量、百分比和正在处理的资产；
- 扫描期间可取消，取消扫描不会修改项目内容；
- 已计算的完整指纹会建立索引并缓存到项目的 `Saved/AXICleanCache/FingerprintIndex.bin`；
- 后续扫描仍会通过 Asset Registry 清点比较范围，但只有新增、修改、Dirty 或缓存失效的候选资产需要重新加载并计算完整指纹；
- 纹理载荷指纹覆盖全部数据块、图层和 Mip；
- 分开比较纹理载荷与会影响行为的设置；
- 将结果分类为“安全重复项”“需要复核”“相似项”或“冲突”；
- 可按上述重复类别筛选结果，摘要同时显示缓存命中数与本次增量计算数；
- 只允许“安全重复项”进入整理队列；
- 执行前重新验证指纹、资产存在性和受影响包的可写性；
- 通过 Unreal 原生 `UEditorAssetSubsystem::ConsolidateAssets` 整理资产和重写引用；
- 操作后验证主资产、来源资产和原引用关系；
- 不会以强制删除作为失败后的兜底方案。

## 使用方法

### 从窗口扫描

在 Unreal 编辑器的“窗口”菜单中选择“内容整理器”。确认窗口中显示的“清理目标”和“重复比较范围”后，点击“开始扫描”。扫描完成后，可以查看重复组、判定依据和设置差异，再将确认安全的组加入队列、执行预检并明确确认整理。

### 整理指定目录

在内容浏览器中右击一个或多个目录，选择“整理此目录的重复内容”。工具窗口会打开，并将所选目录设为**清理目标**，但不会自动扫描。

默认行为是：

```text
清理目标：所选目录
重复比较范围：/Game
```

点击“开始扫描”后，工具会从整个 `/Game` 中寻找与清理目标重复的内容。结果只保留至少包含一个清理目标资产的重复组；执行整理时，也只有清理目标内的资产允许成为待整理来源。工程其他目录中的等价资产可以作为主资产和比较参照，但不会因为本次目录清理而被删除。

引用重定向仍由 Unreal 原生整理接口完成，因此项目中指向被整理来源资产的引用会一并更新。

## 安全原则

1. 扫描是只读阶段，修改必须通过独立且显式的操作完成。
2. 选择目录只设置清理目标，不得隐式触发扫描或修改。
3. 清理目标限制哪些资产可以成为整理来源；比较范围只负责发现重复项。实际修改还可能涉及范围外的引用包，新阶段要求在预检中列出并明确确认。
4. 不会为了寻找重复项而一次性加载整个工程的所有资产。
5. 不使用原始 `.uasset` 文件是否相同作为语义重复的证明。
6. 载荷等价与行为/设置等价分别验证。
7. 不确定或仅仅相似的资产绝不会自动清理。
8. 使用 Unreal 官方整理接口替换引用和处理来源资产。
9. 修改前必须重新验证，防止使用过期扫描结果。
10. 指纹缓存只用于扫描加速；执行整理前仍会绕过缓存并重新计算主资产和待整理资产的指纹。
11. “接口报告失败”和“执行后验证失败”都表示项目可能已经变化，不会被当作可直接重试的普通失败。
12. 可回收空间只统计当前清理目标中能够进入安全整理计划的资产。

## 扫描流程

```text
选择清理目标
 -> 确认比较范围（默认 /Game）
 -> 用户显式点击开始扫描
 -> 资产注册表清点比较范围
 -> 低成本候选分桶
 -> 唯一候选集合
 -> 校验 Saved/AXICleanCache 指纹索引
 -> 复用未变化资产的完整指纹
 -> Texture2D 源数据提取
 -> 载荷指纹
 -> 设置指纹
 -> 安全 / 复核分类
 -> 只保留涉及清理目标的重复组
 -> 优先选择清理目标外的等价资产作为主资产
 -> 审查并选择整理项
 -> 整理队列（来源资产强制限制在清理目标内）
 -> 只读预检
 -> Unreal 原生整理与引用重定向
 -> 操作后验证
 -> 可选的独立重定向器预检、确认与清理
```

## 构建与测试

在安装了对应 Unreal Engine 的 Windows 机器上打包插件：

```powershell
.\Scripts\Build-Plugin.ps1 -EngineVersion 5.5
.\Scripts\Build-Plugin.ps1 -EngineVersion 5.8
```

生成的 Win64 编辑器插件位于 `dist\UE5.5` 和 `dist\UE5.8`。

测试入口支持两个版本，复制源码到唯一临时目录，并构建专用测试宿主 Editor 目标。每次运行只使用自己的插件副本和生成资产；构建禁止修改引擎文件，后台进程降低优先级，最多两个编译任务。自动化结果、命令与清理记录保留在 `Saved/Validation/`。支持入口不等于已通过验收，具体结果见 [`docs/VALIDATION_2026-10-28.md`](docs/VALIDATION_2026-10-28.md)。

```powershell
.\Scripts\Test-Plugin.ps1 -EngineVersion 5.5
.\Scripts\Test-Plugin.ps1 -EngineVersion 5.8
```

脚本不创建指向原仓库的目录联接，也不写入正在打开的生产工程。可以用 `-EngineRoot`、`-CompilerVersion`、`-ResultsDirectory` 指定本机工具链和证据目录。

## 单资产孤岛流程

切换到“清理孤岛素材”，设置目标并显式扫描。分类为“未发现外部引用（候选）”只表示注册表观察结果；检查器显示硬/软/管理引用、保护/未知状态、材料元数据和动态加载覆盖限制。材质槽不决定网格是否被使用。

将候选逐项加入删除队列，运行只读预检，检查确切目标、包大小估算与阻止原因，确认后服务逐项复查，再走 Unreal 普通删除路径并检查资产/包消失及已观察依赖包保留。不会扩展到依赖或新暴露的候选。任何修改调用后，原计划不可重放；失败可能已部分修改，必须重新扫描。两种模式的结果、队列和汇总会同时失效。

当前删除白名单为精确类 `Texture2D`、`Material`、`MaterialInstanceConstant`、`StaticMesh`、`SkeletalMesh`。其他子类/状态排除；引擎、插件、开发者、外部对象目录、Primary Asset、已知引用、脏/未保存/只读包、同包其他对象、外部包/外置载荷文件、内存/撤销/资产编辑器占用和不可确认的源控制状态会阻止删除。已注册引用查询覆盖整个可用注册表，不限于目标或候选类型。无法排除代码、配置和动态字符串加载，确认时必须理解此限制。

重复整理支持手动选择已证明等价的主资产；推荐顺序为范围外等价资产优先，再按引用数、较短路径和字典序。批次预检展示所有影响包、范围外影响和多组共享引用包。独立组可在一次确认后连续执行；只接受前序已验证的精确引用替换及已审查包的保存状态变化，外部新增影响或非预期变化仍会停止。重叠资产组会提前阻止。部分失败后保留未执行目标的只读明细，所有旧计划失效。引用验证按对象/属性核对硬/软引用目标及数量，而不只检查旧引用消失。

重定向器清理仅在整理验证成功后单独提供，拥有自己的预检与确认。目前采取保守策略：只处理计划范围内、无剩余注册/加载/撤销用户的单对象可写重定向器包，且要求关闭源控制；其他情况明确阻止。不会静默修复重定向器。
